# 🧠 Project Context

## 🧪 Project

**OrangeHRM Cypress**

---

## 📌 Project Context

OrangeHRM Cypress es un proyecto de automatización de pruebas de interfaz de usuario desarrollado originalmente con Cypress, JavaScript y Node.js.

El proyecto ya contaba con una implementación funcional y publicada en GitHub antes de iniciar la etapa actual de estandarización.

La finalidad de esta etapa no es reconstruir ni refactorizar la automatización existente, sino mejorar su organización, documentación y presentación profesional.

---

## 🎯 Standardization Context

La estandarización de OrangeHRM Cypress se realiza tomando como referencia la estructura y metodología establecida previamente en el proyecto **Urban Routes**.

El objetivo es que los proyectos del portafolio mantengan una identidad común, independientemente de las tecnologías utilizadas.

La estandarización contempla principalmente:

- Estructura documental.
- Organización del repositorio.
- README.
- Convenciones de documentación.
- Registro de decisiones.
- Historial de cambios.
- Roadmap.
- Presentación profesional del proyecto.

---

## 🚫 Frozen Decisions

Las siguientes decisiones se consideran establecidas para esta etapa y no deben modificarse sin una razón justificada:

### 1. No refactorizar el código existente

El código de automatización funcional se conserva tal como fue desarrollado originalmente.

No se modificarán:

- Tests existentes.
- Selectores.
- Comandos Cypress.
- Fixtures.
- Configuración funcional.
- Flujo de automatización.

Cualquier mejora de código deberá considerarse como una etapa independiente.

---

### 2. Mantener el repositorio existente

No se creará un repositorio nuevo.

El proyecto continuará utilizando el repositorio existente en GitHub.

Repositorio actual:

`orangehrm-cypress`

El historial existente debe conservarse.

---

### 3. Mantener Cypress como framework

No se cambiará el framework de automatización.

El proyecto continuará utilizando:

- Cypress
- JavaScript
- Node.js
- npm

---

### 4. Mantener el alcance funcional actual

El proyecto continuará enfocado en la automatización del módulo de:

**Authentication / Login**

No se agregarán nuevos módulos durante esta etapa de estandarización.

---

### 5. Mantener la estructura documental

El proyecto utilizará la siguiente estructura:

```text
docs/
├── CHANGELOG.md
├── CONTEXT.md
├── ORIGINAL_PROJECT.md
├── PROJECT_BRIEF.md
├── PROJECT_STATUS.md
└── ROADMAP.md
```
Esta estructura seguirá la misma lógica utilizada en los demás proyectos estandarizados del portafolio.

---

## 📐 Documentation Principles

La documentación debe cumplir con los siguientes principios:

- Ser clara.
- Ser concisa.
- Mantener una estructura consistente.
- Registrar información relevante del proyecto.
- Diferenciar claramente entre estado original y estado actual.
- Evitar documentar decisiones que no se hayan tomado.
- Mantener trazabilidad de los cambios.
- Evitar información innecesaria o redundante.

---

## 🧩 README Standard

El README seguirá una estructura común para los proyectos del portafolio.

El orden establecido es:
1. 🧪 Título
2. 📌 Descripción
3. 🎯 Objetivos
4. 🛠 Tecnologías utilizadas
5. 🧩 Competencias demostradas
6. 📁 Estructura del proyecto
7. ⚙️ Instalación
8. ▶️ Ejecución
9. ✅ Escenarios automatizados
10. 📋 Casos de prueba automatizados
11. 📸 Evidencias
12. 🚀 Cómo ejecutar el proyecto
13. 📊 Estado del proyecto
14. 👨‍💻 Autor

El contenido será específico para OrangeHRM Cypress, pero conservará el mismo orden e identidad visual establecido para el portafolio.

---

## 🔄 Working Methodology

La estandarización se realizará de manera incremental.

El proceso seguirá este orden general:
1. Analizar.
2. Documentar.
3. Estandarizar.
4. Revisar.
5. Registrar cambios.
6. Actualizar GitHub.

No se realizarán cambios masivos sin revisión previa.

---

## 🔍 Analysis Before Modification

Antes de modificar cualquier elemento del proyecto se deberá:

* Analizar su estado actual.
* Determinar si el cambio es necesario.
* Compararlo con la estructura estándar.
* Evaluar si afecta la funcionalidad existente.
* Confirmar que el cambio pertenece al alcance de la estandarización.

La prioridad es preservar la funcionalidad existente.

---

## 📊 Project Philosophy

El proyecto debe evolucionar hacia una estructura profesional sin perder su identidad ni su historial.

La estandarización busca demostrar no solamente conocimientos de automatización, sino también capacidad para:

* Organizar proyectos.
* Documentar procesos.
* Mantener trazabilidad.
* Gestionar versiones.
* Tomar decisiones técnicas.
* Mantener proyectos de automatización a largo plazo.
